# XKeen Setup

Полная установка прокси на **ARM64 Keenetic/Netcraze после ручной установки Entware**. Один автономный `install.sh`: XKeen, Xray, веб-панель, преобразование подписки, первоначальная проверка серверов, автозапуск и резервное сохранение списка.

## Быстрый старт

Подключитесь к Entware по SSH как root и выполните одну команду:

```sh
opkg update && opkg install curl ca-bundle && \
curl -fL https://raw.githubusercontent.com/ixarek/xkeen-addons/main/install.sh -o /tmp/xkeen-install.sh && \
sh /tmp/xkeen-install.sh
```

Первая часть позволяет скачать установщик в чистом Entware. Всё последующее делает один файл. Можно вместо скачивания скопировать `install.sh` на роутер и выполнить `sh install.sh`.

Скрипт запросит HTTPS-ссылку подписки скрытым вводом. Затем установит компоненты, импортирует VLESS-серверы, проверит их HTTPS-запросом через прокси и выберет первый рабочий. Если прежний выбранный сервер сохранился в подписке и проходит проверку, он останется выбранным. После установки переключение серверов **ручное**, постоянного автоматического failover нет.

В конце появятся адрес панели, результат проверки и путь к резервной копии. Обычно панель открывается на `http://192.168.1.1:3000`; установщик пытается определить фактический LAN-адрес.

## Действия пользователя

1. Заранее установить Entware и настроить обычный интернет на роутере.
2. Ввести URL подписки в установщике.
3. При первом открытии новой панели создать аккаунт и подключить TOTP в приложении-аутентификаторе. Скрипт не создаёт общего пароля и не отключает защиту панели.
4. В интерфейсе Keenetic назначить нужные устройства политике **XKeen**. Назначения устройств сохраняются под контролем пользователя.

**KeeneticOS 5.2+:** если локальный RCI защищён, установщик дополнительно попросит токен, созданный в «Пользователи и доступ». На прошивках без этого требования вопроса нет. [Инструкция upstream](https://github.com/jameszeroX/XKeen/wiki/Порядок-установки).

## Состав и требования

- ARM64/aarch64 Keenetic/Netcraze, Entware, root SSH и `ndmc`.
- От **48 МиБ** свободного места в `/opt` для чистой установки; **32 МиБ** при установленных XKeen/Xray. Это предварительный порог, а не гарантия для любой прошивки и сторонних пакетов. Установщик ядра также проверяет место.
- Работающий интернет, DNS, корректные часы и доступ к Entware/GitHub. USB не требуется, если Entware установлен во внутреннюю память.
- Для новой установки: XKeen **2.1**, Xray **v26.9.30**, XKeen Panel **v1.3.0**, xkeen-subscription-watcher **v0.4.0**. Существующие версии автоматически не обновляются.
- Только Xray. Mihomo, GeoSite/GeoIP и GeoIPSET не устанавливаются, поскольку предоставленная маршрутизация их не использует.
- Зависимости устанавливаются через opkg и штатный XKeen. Массовое `opkg upgrade` не выполняется.

Используется поддерживаемый upstream авто-режим, без подачи `yes` в меню:

```sh
xkeen -i auto cores=xray xray=v26.9.30 geo=off geoipset=off cron=off autostart=on
```

[Параметры автоустановки](https://github.com/jameszeroX/XKeen/blob/main/wiki/autoinstall.md). Архив XKeen и бинарники панели/конвертера проверяются по закреплённым SHA-256. Xray устанавливает штатный XKeen по указанной версии. Сторонние бинарники не входят в репозиторий.

## Проверка без установки

```sh
sh /tmp/xkeen-install.sh --check
```

Проверяются локальные требования и выводится план. Пакеты и файлы не меняются. Этот режим не проверяет будущую подписку или доступность всех загрузок.

## Маршрутизация и повторный запуск

При новой установке стандартные входы `redirect`, `tproxy`, `force-proxy-redirect`, `force-proxy-tproxy` направляются в выбранный `vless-reality`; локальные IP-адреса идут напрямую.

Создаваемой политике XKeen разрешаются интерфейсы, объявленные глобальными интернет-подключениями в Keenetic, включая WAN и Wi-Fi WAN. У существующей политики разрешения сохраняются. Установщик проверяет default-маршрут её таблицы. Назначения устройств не меняются.

Повторный запуск сохраняет аккаунт панели, установленные ядра и пользовательскую маршрутизацию. Нестандартная маршрутизация должна ссылаться на `vless-reality`; иначе скрипт завершится с объяснением. Перед изменениями создаются резервные копии в `/opt/etc/xserver/`. Совместимость с произвольной конфигурацией стороннего проекта не гарантируется.

Если подписка недоступна или все серверы не прошли HTTPS-проверку, установка завершается с ошибкой; панель остаётся для диагностики. Сообщения об успешном соединении в этом случае нет. Перебор недоступных серверов может занять несколько минут, прогресс показывается по номерам.

## Подписки и ручной выбор

```sh
xsub change       # Ввести новую HTTPS-ссылку и загрузить список
xsub update       # Обновить список по сохранённой исходной ссылке
xserver           # Список и интерактивный ручной выбор
xserver list      # Только список
xserver ping 51   # Проверить HTTPS-запрос через сервер 51
xserver use 51    # Выбрать сервер 51
```

В меню: число переключает сервер, `p 51` проверяет его, `q` выходит. Номера могут меняться при обновлении подписки. Проверка требует HTTP 204 от контрольного адреса и показывает время полного HTTPS-запроса через прокси, а не ICMP-пинг. Кнопка «Пинг» в панели использует собственную реализацию.

Поддерживаются обычные URI-списки и Base64-подписки с VLESS, включая Reality/TLS и TCP/gRPC/XHTTP/WS. Остальные протоколы исключаются из списка панели, а не преобразуются в VLESS. Исходный скачанный файл сохраняется. JSON/YAML, личные кабинеты, зашифрованные подписки и схемы вроде `happ://` не поддерживаются.

После обновления подписки обновите страницу панели. Её ссылка — `http://127.0.0.1:18080/vless.txt`, локальная подготовленная копия. Кнопка обновления панели перечитывает её; загрузку у провайдера выполняет `xsub update`. Не заменяйте локальную ссылку исходной ссылкой неподдерживаемого формата.

Смена подписки сохраняет текущую конфигурацию Xray до ручного выбора сервера. Если прежнего сервера нет в новом списке, его активная отметка снимается. Периодическая загрузка подписки и автоматическое переключение серверов после установки не включаются.

## Только дополнения к уже установленному XKeen

Сохраняется [отдельный установщик и инструкция](docs/addons.md):

```sh
sh install-xkeen-addons.sh --check
sh install-xkeen-addons.sh
```

Опция `--configure-routing` заменяет `05_routing.json` стандартной маршрутизацией после резервного копирования. Для существующих пользовательских правил запускайте без неё. Затем `xsub change` и `xserver`.

## Сохранение и секреты

`xsub-guard` проверяет список при запуске панели, сохраняет исправный снимок перед штатной остановкой и раз в минуту через cron. На flash записываются только изменённые снимки. Повреждённый файл восстанавливается из последней исправной копии. Аварийное питание может потерять последние изменения до создания снимка.

URL хранится в `/opt/etc/xserver/source-url` с доступом только root. URL, RCI-токен, список и резервные копии содержат секреты — не публикуйте их. TLS-проверка не отключается. В репозитории пользовательских секретов нет.

## Разработка и проверка

Исходники: `scripts/`, шаблоны: `tools/*.template.sh`. Пересборка обоих автономных установщиков:

```powershell
pwsh -File tools/build.ps1
```

Офлайн-тесты запускают настоящий shell/jq с изолированными файлами и подменёнными загрузкой и ядром:

```sh
python3 tests/test_setup.py
```

На Windows задайте `BASH_BIN` и `JQ_BIN`. GitHub Actions проверяет пересборку, BusyBox ash и тесты. Покрываются конвертация, Unicode/IPv6, сохранение выбора, ошибки загрузки/формата, проверка HTTP, первоначальный выбор сервера и `--check` на имитации чистого Entware.

Команды и восстановление списка ранее проверены на ARM64-роутере. **Полная установка нового сценария на чистом физическом роутере пока не проверена.** Офлайн-тесты не проверяют пакеты, прошивку, доступность upstream или аппаратные ограничения.
