# Mihomo TUN на Keenetic с Entware на USB

Отдельный сценарий для чистого **ARM64/aarch64 Keenetic**, где Entware вручную установлен на USB. Устанавливает Mihomo **v1.19.32**, MetaCubeXD **v1.273.1**, локальный импорт подписки, автозапуск и управление. XKeen, Xray и прежняя XKeen Panel не устанавливаются.

## Установка

После сброса роутера сначала восстановите обычное подключение к интернету (WAN и/или Wi-Fi WAN), установите Entware **на USB**, подключитесь к Entware SSH как root. На этапе скачивания нужен доступ к Entware, GitHub и провайдеру подписки.

```sh
opkg update && opkg install curl ca-bundle && \
curl -fL https://raw.githubusercontent.com/ixarek/xkeen-addons/main/install-mihomo-tun.sh -o /tmp/install-mihomo-tun.sh && \
sh /tmp/install-mihomo-tun.sh
```

Установщик запросит:

Если нужный ПК ещё не подключён, запускайте `sh /tmp/install-mihomo-tun.sh --prepare`: установятся ядро, TUN и панель, но новые устройства не будут назначены. Позже добавьте ПК командой `mtun clients IPv4 MAC`. При повторном `--prepare` существующий список устройств сохраняется.

1. HTTPS URL подписки (скрытый ввод).
2. Локальный IPv4 нужного ПК, например `192.168.1.50`.
3. MAC этого ПК: обнаруженное значение можно принять Enter. Адреса видны в интерфейсе Keenetic, команды на ПК не нужны.

**Закрепите IPv4 ПК в настройках DHCP Keenetic.** Перехват основан на указанном IPv4; MAC используется для блокировки обхода по IPv6. Это отдельный механизм, не привязка к политике XKeen. Остальные ПК автоматически в TUN не включаются. Используется основная LAN-сеть `br0`; гостевые VLAN и IPv6-туннелирование этим установщиком не настраиваются.

Проверка требований без установки:

```sh
sh /tmp/install-mihomo-tun.sh --check
```

Минимальные предварительные пороги: **256 МиБ свободного места на USB** и **128 МиБ доступной оперативной памяти**. USB добавляет место для файлов, но не RAM. До настройки маршрутизации проверяется `/dev/net/tun`, при возможности загружается модуль `tun`. Если прошивка не поддерживает TUN, скрипт остановится с объяснением. Наличие файла устройства само по себе недостаточно: после запуска также проверяется фактический интерфейс `mhtun0`.

## Что получается

```text
Корпоративный VPN на ПК
        ↓
Keenetic: маршрут выбранного ПК в mhtun0 (настоящий TUN)
        ↓
Mihomo → выбранный сервер подписки → корпоративный VPN-шлюз
```

Настройки корпоративного VPN и HTTP-прокси на ПК остаются прежними. Корпоративный прокси, доступный внутри поднятого VPN, должен достигаться через маршруты этого VPN на самом ПК.

Используется TUN-стек `gvisor`, MTU 1400. Автоматические `auto-route`/`auto-redirect` выключены: скрипты явно создают IPv4 source routing для выбранных ПК с приоритетом 100 и таблицей 2023. На чистой установке занятые таблица/приоритет вызывают остановку. Это не REDIRECT/TPROXY для пользовательских соединений; NAT применяется отдельно только для DNS.

Для возвратных пакетов TUN отключается strict `rp_filter` на `all`, `br0` и `mhtun0`; исходные значения восстанавливаются при явном `mtun stop`, если пользователь не поменял их после запуска. Индивидуальные настройки WAN-интерфейсов не меняются. Для TCP ограничивается MSS с учётом MTU туннеля.

Прямо доступны адреса самого роутера и подключённой основной LAN. Широких исключений для всех `10/8`, `172.16/12`, `192.168/16` нет. Остальной TCP/UDP передаётся выбранному серверу. TUN не превращает VLESS/Trojan в универсальный перенос произвольных IP-протоколов: например, поддержка GRE/ESP этим сценарием не обещается. Работоспособность конкретной корпоративной программы проверяется на ПК.

DNS выбранного ПК на TCP/UDP 53 направляется в Mihomo; внешние запросы Mihomo идут по DoH через группу `PROXY`. Используется `redir-host`, без подмены ответов на fake IP. Для первоначального разрешения имени **самого прокси-сервера** используется системный DNS роутера; этот DNS должен работать в вашей сети. DNS внутри зашифрованного корпоративного VPN роутер не перехватывает.

IPv6-forwarding выбранного MAC блокируется, чтобы не получить незаметный прямой обход. Выходы самого роутера и остальных устройств остаются штатными; WAN/Wi-Fi WAN выбираются обычной маршрутизацией Keenetic, Mihomo отслеживает выходной интерфейс.

## Панель и серверы

В конце установки выводятся адрес `http://LAN_IP:9090/ui/` и случайный **Secret**. В MetaCubeXD добавьте адрес API `http://LAN_IP:9090` и этот Secret. Панель обслуживается локально, интернет для загрузки её файлов после установки не нужен. Слушатель API привязан к LAN IPv4 роутера; не открывайте его пробросом портов наружу.

В группе **PROXY** можно выбрать сервер, проверить задержку и посмотреть подключения. Выбор сохраняется в базе Mihomo на USB. Постоянное автоматическое переключение серверов не включено. При установке проверяется текущий сервер, затем остальные до первого, вернувшего HTTP 204 от контрольного HTTPS-адреса.

```sh
mtun panel       # Адрес панели и Secret (содержит секрет)
mtun list        # Список, номера и выбранный сервер
mtun use 5       # Выбрать сервер 5
mtun ping 5      # HTTPS-проверка сервера 5; затем восстановить прежний выбор
mtun best        # Оставить рабочий текущий или выбрать первый рабочий
mtun update      # Скачать свежую подписку по сохранённой ссылке
mtun change      # Ввести другую HTTPS-ссылку
mtun clients     # Устройства в TUN
mtun clients 192.168.1.50 aa:bb:cc:dd:ee:ff
mtun status
mtun check
mtun stop        # Отключить TUN и вернуть обычную маршрутизацию
mtun start       # Включить TUN и автозапуск снова
```

`mtun ping` временно переключает общую группу PROXY: проверка может повлиять на соединения ПК. Метрика — время HTTPS-запроса, не ICMP. Обновление подписки и изменения клиентов выполняются через SSH роутера. Панель умеет выбирать серверы, но не заменяет команду `mtun change` для исходной подписки.

## Подписки и хранение

Используется **встроенный импорт file-provider Mihomo**, который умеет читать URI/Base64 и YAML с полем `proxies`. Доступные протоколы/транспорты определяет закреплённая версия Mihomo. Есть VLESS, Trojan, Shadowsocks и другие поддержанные ядром схемы. Неподдерживаемые ссылки могут быть пропущены либо вызвать ошибку провайдера; Xray-специфичные транспорты не считаются автоматически совместимыми. Сторонний онлайн-конвертер не используется, URL ему не передаётся.

Подписка помещается в отдельный file-provider и не может заменить слушатели/API/маршрутизацию основной конфигурации. Перед обновлением проверяется загрузка узлов отдельным экземпляром настоящего ядра с выключенным TUN. Ошибка загрузки/разбора сохраняет прежний список. При обновлении сначала пробуется загрузка через действующий прокси, затем напрямую.

Файлы находятся в `/opt/etc/mihomo-tun/` (USB): `config.json`, `source-url`, `subscription.txt`, `clients`, база выбора и панель `ui/`. Права конфигурации — только root. Резервные копии содержат URL/ключи и **не предназначены для публикации**. SHA-256 архивов ядра и панели закреплены в установщике. Повторная установка создаёт новую резервную копию; старые копии можно удалить вручную, когда они больше не нужны.

## Автозапуск и диагностика

Сервис `/opt/etc/init.d/S80mihomo-tun`, callback Keenetic в `netfilter.d` и cron раз в минуту восстанавливают процесс и правила после изменений. При падении ядра в таблице остаётся `unreachable`, чтобы настроенные IPv4-клиенты не переключались незаметно на прямой WAN. **Это не защита до запуска Entware при загрузке роутера и не гарантия при извлечении USB или полном сбросе firewall.** Явный `mtun stop` снимает правила и возвращает прямую маршрутизацию.

Журнал ядра находится в RAM: `/tmp/mihomo-tun/core.log`. Не публикуйте журнал без просмотра: ошибки разбора подписки могут содержать параметры серверов. Если все узлы недоступны, успешного завершения установки нет: панель остаётся для выбора, а выбранный ПК остаётся под ограничивающими правилами. Для обычного интернета выполните `mtun stop`.

В конфигурации не отключается аппаратное ускорение всей домашней сети. Поведение ускорения/conntrack конкретной прошивки и реальное прохождение трафика ПК нужно проверить на роутере; локальные тесты их не моделируют. При первичном включении удаляются старые conntrack-сессии только выбранного ПК.

Тесты проверяют встроенный импорт Base64 с VLESS/Trojan, API/авторизацию и выбор серверов на настоящем Mihomo, а также конфигурацию и команды маршрутизации в изоляции. **Полная установка на физическом Keenetic после сброса пока не проверена.**
